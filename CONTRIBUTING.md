# Contributing

This repository is a **mirror**. The client is developed inside CraterView's platform
repository, alongside the API it speaks to and the model catalogue it carries defaults from,
and it is copied here whenever a version is released. Every file outside `.github/` is
generated by that copy.

So a pull request opened here cannot be merged as-is — the next release would overwrite it.
That is not a brush-off, and it is worth saying what happens instead:

- **Issues are the right channel and they are read.** Bug reports, missing features, unclear
  documentation, a signature that does not match what the API actually returns — open an issue
  and it is triaged with everything else.
- **A pull request is welcome as a proposal.** It is the clearest possible bug report: it says
  exactly what you would change. It gets ported upstream with attribution, and the issue or PR
  is closed when the release carrying it goes out.
- **Security reports do not belong in an issue.** Mail security@craterview.ai instead.

## Why the client is not developed here

The client ships defaults — model names, parameter names, the limits it validates against —
that have to agree with what the API serves. Upstream, the test suite checks the two against
each other on every commit, so a model renamed in the catalogue and not in this client fails
before it is released rather than 404ing for whoever installed it. Splitting the client into
its own source repository is what would remove that check.
